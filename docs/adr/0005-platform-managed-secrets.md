# 模型密钥可加密存储，其余凭据仍由平台密钥管理注入

Status: accepted

模型密钥与 MCP 凭据默认由 K8s Secret 或 Vault 等平台密钥管理注入，AI 数据库只存引用。唯一的例外是平台运营在控制台直接填写的模型 API Key：它由 AI 服务用部署注入的主密钥加密后存入模型目录，运行时解密再发给供应商；MCP 凭据仍只按租户派生引用并注入。平台运营在浏览器表单输入的模型 API Key 仅经写入请求提交，任何 HTTP 响应都不返回原始密钥；Runner 上下文、审计与日志也不包含原始密钥。

把密钥放进业务表会扩大备份、导出与日志的敏感范围，所以默认仍是引用。但模型厂商 Key 必须原样回放给供应商，摘要不可行；而每接入一个模型就改一次部署 Secret 并重启服务，会让“平台运营维护模型目录”退化成一张运维工单。为模型凭据开这一条例外，用独立主密钥、AAD 绑定模型 ID 与“只写不读回”把风险限制在可接受范围。

## Considered Options

- 只保留环境变量引用：目录页面只能改元数据，新增模型仍需运维介入。
- 明文入库：备份与导出直接泄露全部 Key，否决。
- 对 Key 存摘要：无法回放给供应商，不可行。

## Consequences

- `AI_MODEL_CREDENTIAL_KEY` 成为 AI 服务的必配项，缺失即启动失败；它丢失后已加密的模型 Key 无法恢复，只能重新录入，v1 没有轮换流程。
- 编辑时留空表示保持密钥、填写表示替换；不提供“清除密钥”，要停用模型就禁用。
- 引用型模型继续可用，迁移只打类型标记，不从环境变量回写数据库。
- 与 SaaS Forge 的 ADR-0023（服务凭证只存摘要、否决对称加密）不冲突：服务凭证只需比对，模型 Key 必须回放，两者威胁模型不同。
